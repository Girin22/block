# 미니멀 V2

개발 서버 전용 대량 기록 테스트는 `?stress=600` / `1200` / `3600` / `172800`으로 열 수 있다. 현재 저장 규칙과 측정은 [고해상도 한 장 저장](highres-export.md), 이전 측정은 [긴 영수증 테스트](receipt-stress.md)를 참고한다. 프로덕션과 일반 진입에서는 활성화하지 않는다.

세션 한도는 초록 블록 172,800개(24×60×60×2)다. 흰 자동 타일은 한도를 소모하지 않는다. 실제 플레이 시간이나 입력 빈도를 측정하는 규칙이 아니라 0.5초당 한 개를 24시간 놓은 양으로 정한 개수 제한이다. 한도 도달 후 활성 타일과 실루엣을 숨기고 입력·자동 낙하를 막는다. 일시정지 메뉴에서 Resume는 비활성화하고 Export로 기존 기록을 저장할 수 있다. 저장 후 새 세션에는 한도를 다시 적용한다.

영수증 헤더는 12px 크기의 날짜·조각 수 한 줄이며, 바로 아래에 은은한 스티치 점선(3/4)을 유지한다. 미리보기와 저장 이미지에 동일하게 적용한다.
조각이 0개라면 숫자를 생략하여 `YYYY.MM.DD · piece`로 표시한다.

새 세션은 게임 화면을 처음 터치할 때까지 자동 낙하를 시작하지 않는다. 블록이 아닌 빈 게임 화면에서도 조작할 수 있다. 첫 터치 이후에는 다음 타일도 자동으로 낙하하며, 누르고 있는 동안 멈춘다. 메뉴 터치는 시작으로 취급하지 않는다. 테스트용 게임 조작 키도 시작 입력으로 인정한다. 새로고침과 Export 저장 후 새 세션에서는 다시 첫 터치를 기다린다.

입력 개선: 게임 화면 어디서든 탭으로 회전하고 스와이프로 이동한다. 12px 이상 움직이고 한 축 이동이 다른 축의 1.25배 이상이면 해당 제스처를 가로 또는 세로로 고정한다. 세로 제스처는 좌우 이동 없이 아래로만 내리고, 가로 제스처는 높이를 유지한다. 방향을 바꾸려면 손을 떼고 다시 스와이프한다. 회전은 현재 칸, 왼쪽 한 칸, 오른쪽 한 칸 순서로 빈 공간을 검사하며 위로 들어 올리거나 충돌을 무시하지 않는다.

빠른 안착 판정은 아래 방향 순이동 48 CSS px 이상이며 세로 이동이 가로 이동보다 클 때만 인정한다. 기존 75% 높이 조건도 함께 적용한다. 작은 드래그나 좌우 조정 후에는 현재 높이에서 일반 자동 낙하를 이어간다. 자동 낙하 자체에는 스와이프가 필요하지 않다.

저장 이미지에는 상단 중앙에 `YYYY.MM.DD · 00조각` 한 줄만 작은 글씨로 표시한다(2026-09-22까지는 `00 piece`). 조각 수는 흰 타일 포함 전체 개수이며 최소 두 자리로 표시한다. 브랜드·장식·저장 안내 문구는 제거하고 화면의 닫기/이미지 저장 동작은 유지한다. 저장 실패 시에만 오류 안내를 표시한다.

기존 소스와 데이터는 PC에 그대로 보존한다. Git 업로드와 기본 빌드에는 V2 진입점 `index.html`만 포함한다. `/legacy/`, V1 소스/패키지/테스트는 Git에서 제외하며 V2는 이 파일들을 참조하지 않는다.

게임판은 폭 9칸이다. 굴곡진 긴 인터로킹 블록 한 종류를 90도 회전하고, 세로 또는 가로 두 칸을 차지한다. 공유된 곡선 경계를 회전 대칭으로 만들어 모든 방향에서 맞물린다. 게임 화면을 누른 채 스와이프하며 위로 이동할 수 없다. 누르고 있는 동안 자동 낙하를 멈추고, 손을 놓으면 원위치 복귀 없이 현재 높이에서 낙하를 이어간다. 바닥 기준 75% 선 아래에서 의도적인 아래 스와이프로 내려놓으면 빠르게 안착한다. 탭 회전은 최대 한 칸의 좌우 보정을 포함해 충돌하지 않을 때 허용한다. 현재 높이의 실제 점유 칸으로 충돌을 판단하여 덮개 아래 열린 틈새에도 옆에서 들어갈 수 있다. 활성 블록은 초당 1.1칸 자동으로 내려가고, 바닥 접촉 0.45초 후 고정된다. 일시정지 중에는 하강·고정 타이머가 멈춘다. 이미 놓인 블록의 물리 중력·줄 지우기·게임 오버는 없다. 빈 한 칸의 상하좌우가 모두 막히면 흰 타일을 자동 생성한다. 주변 블록 종류나 대각선은 무관하고, 벽과 활성 바닥도 막힌 면으로 취급한다. 두 칸 이상 연결된 빈 공간은 채우지 않는다.

조작 반응: 세로 드래그 중에는 손의 이동량에 따라 높이를 내린다. 카메라는 입력·착지 중에도 속도가 연속적인 감쇠 추적으로 부드럽게 이동한다. 조작 중 활성 블록은 카메라 이동량을 보정하고 활성 바닥 상승은 멈춘다. 빠른 안착은 남은 거리에 따라 100~380ms 동안 점점 가속하며 착지 직전에 감속하지 않는다. 착지 시 기존 효과음을 재생한다(눌림·복원 효과는 2026-09-21에 제거, 아래 기록 참고). 일반 자동 낙하 속도와 75%/48px 안착 판정은 유지한다. 일시정지 메뉴의 두 버튼은 배경·글자·호버 색을 동일하게 사용한다.

카메라는 쌓인 높이를 화면 중간에 유지한다. 활성 블록은 카메라 상단에서 시작한다. 화면 아래를 지난 곳에는 블록을 떨어뜨릴 수 없도록 활성 바닥을 올린다. 지나간 메시와 충돌 셀을 해제하되, 실제 배치 목록은 이번 플레이의 영수증 출력을 위해 메모리에 보관한다.

V2는 브라우저 저장소를 읽거나 쓰지 않는다. 화면을 완전히 나가거나 새로고침하면 초기화하고, BFCache로 되돌아와도 새로 시작한다. 단순 탭 전환은 일시정지한다. Export는 거리 없이 실제 블록 배치 전체를 가상 스크롤 영수증으로 보여준다. 미리보기가 열리면 파일을 준비하고 사진 저장 클릭에서 기기 메뉴를 연다. iPhone에서는 사용자가 ‘이미지 저장’을 선택한다. 메뉴 API 완료 후 초기화하며 취소·실패 시 유지한다. API 완료는 실제 사진 앱 저장 완료를 보장하지 않는다. HTTP LAN 등 메뉴 미지원 환경에서는 PNG를 길게 눌러 저장한 뒤 ‘저장 완료’로 초기화한다. SVG는 명확한 파일 저장 안내와 버튼을 제공하며 다운로드 요청 후 초기화한다. 브라우저는 실제 파일 저장 완료를 알려주지 않는다. 미리보기를 닫으면 세션을 유지한다.

PNG는 축소 없이 2배 배율(가로 688px)로 유지하며, 256행씩 그려 하나의 PNG 파일로 압축한다. 전체 비트맵을 만드는 캔버스를 생성하지 않는다. 3,200만 픽셀 또는 세로 65,536px 초과, 압축 API 미지원, PNG 생성 실패 시에는 SVG 한 장으로 전환한다. SVG 윤곽은 defs/use로 재사용하며 최대치 기록도 모든 개별 타일의 위치와 색을 유지한다. 파일 생성 도중 미리보기를 닫으면 작업을 취소한다. iOS 실기기 사진 저장/최대 확대 지원 범위는 별도 확인이 필요하다. 효과음 합성은 `apps/play/src/audio.ts`에 두며 V1 설정/소스에 의존하지 않는다(소리 자체는 2026-09-21에 교체, 아래 기록 참고).

일시정지는 팝업을 열지 않는다. 낙하 블록·실루엣을 숨기고 쌓인 보도는 유지하며, 플레이 시간·초록 블록 수·흰 블록 수·Export가 아래에서 올라온다. 시간은 최초 게임 입력부터 세며 일시정지·Export·백그라운드 체류 시간은 제외한다. 거리 환산은 추가하지 않는다. 버튼은 `assets/images/Flow 2.lottie`를 정방향으로 재생해 고깔이 되고 재클릭하면 현재 프레임에서 역방향으로 재생해 일시정지 아이콘으로 돌아간다. Resume 글씨는 표시하지 않으며 모션 감소 설정에서는 끝 프레임만 표시한다. 플레이어와 WASM은 앱에 포함하고 외부 CDN에 의존하지 않는다.

Export만 기존 이미지 저장 모달을 연다. 닫기·Escape는 일시정지 화면으로 돌아오고, 저장 완료 시 새 세션으로 재개한다. 저장 취소·실패 시 배치를 유지하고, 세션 한도 도달 시 재개 버튼은 비활성화하되 Export는 사용할 수 있다.

2026-10-02 환경음 AAC 적용: 거리 네 곡과 빗소리를 AAC 160kbps 스테레오(`.m4a`)로 바꿨다. 녹음이 실제 스테레오라 모노로 줄이지 않았다. 블라인드 비교에서 128kbps도 원본(MP3 320kbps)과 구분되지 않았지만 여유를 두어 160kbps로 정했다. 음량은 원본과 0.2dB 이내, 길이는 같아 기존 LUFS 보정값을 유지한다. 원본 MP3는 `assets/audio`에 보존한다. 빌드 크기 27MB → 16MB.

2026-10-03 온보딩 글씨·인트로 표시 방식: 온보딩 글씨를 시안의 1.5배로 키웠다(`onboardingSize`, PC 높이 900px 기준 약 27px). 1.5배에서도 PC·휴대폰 모두 인트로 문장이 한 줄에 들어간다. 긴 줄은 넘칠 때 균형 있게 두 줄로 나뉜다. 인트로는 기본으로 한 줄씩 위에서 아래로 부드럽게 드러나며 쓸어내리듯 나타난다(`introSweep`, 한 줄 0.55초, `sweepSeconds`). 관리자에서 ‘한 글자씩 쓰기’로 바꿀 수 있고, 튜토리얼·구멍 안내는 계속 한 글자씩 쓴다. 관리자 패널은 폭 1280px 이상(PC)에서 오른쪽에 항상 붙어 있고, 좁은 화면에서는 ‘조절’ 버튼으로 여는 팝업이다. 왼쪽 아래 관리자 글씨와 버튼을 키웠다.

2026-10-03 글씨 쓰기 감성: 한 글자씩 쓰는 문구는 글자마다 살짝 흐릿하고 0.14em 아래에서 시작해 0.6초에 걸쳐 또렷해지며 제자리에 내려앉는다(`inkSeconds`). 앞 글자가 다 자리 잡기 전에 다음 글자가 시작돼 흐르듯 이어진다. 리듬은 기본 간격(글씨 속도)에 띄어쓰기 1.25배, 쉼표 뒤 0.3초, 마침표 뒤 0.5초, 줄 끝 0.4초를 더하고(`pauseScale`로 배율 조절, 0이면 쉼 없음), 글자 간격을 ±15% 안에서 흔든다(`rhythmJitter`). 첫 구멍 안내의 흰 타일 시작 시점도 이 리듬으로 계산한 시간에 맞춘다. 실측(초당 14자): 글자 사이 70~110ms, 줄 끝 약 0.47초, 마침표+줄바꿈 약 1초.
