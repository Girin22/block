2. 현재 상태 진단

현재 웹 빌드(dist/)는 55MB이며, 대부분 소리 파일입니다.

항목크기비고
거리·비 환경음약 24MB320kbps MP3라 환경음 용도로는 과함
아침·밤 환경음 (비활성)약 29MB개구리C.wav 한 개가 13.6MB
Lottie 재생기 (wasm)1.2MB일시정지 아이콘 하나에 쓰임
손글씨 폰트0.6MB온보딩 문구 수정에 대비해 그대로 유지
게임 코드 + Three.js약 1MB문제 없음
  • 이미 좋음화면 아래로 사라진 블록은 그리지 않고 제거합니다. 환경음은 스트리밍으로 메모리를 아낍니다.
  • 개선보드가 모든 칸을 문자열 키로 저장합니다. 17만 블록에 흰 타일까지 약 40만 칸이면 메모리가 수십 MB로 늘어납니다.
  • 개선일시정지나 대기 중에도 매 프레임 다시 그립니다. 120Hz 기기에서는 초당 120번이고, 발열과 배터리 소모의 주원인입니다.
  • 개선빗방울과 동심원을 매번 새로 만들고 버려서 순간적인 끊김이 생길 수 있습니다.

3. 패키징 방식: Capacitor

Capacitor는 지금의 웹 게임을 앱 안에 그대로 넣고, 휴대폰 내장 브라우저 엔진(Android WebView, iOS WKWebView)으로 실행하는 네이티브 껍데기입니다.

  • 화면, 소리, 조작이 웹 배포본과 같아 퀄리티가 떨어지지 않습니다.
  • 자산을 모두 앱 안에 넣어 오프라인에서도 동작합니다. 애플의 "웹사이트를 감싸기만 한 앱" 거절 사유(심사 지침 4.2)를 피하는 핵심입니다.
  • 앱 껍데기는 약 3~5MB입니다.
  • 나중에 만보기(Health Connect, HealthKit)도 플러그인으로 붙일 수 있습니다.

단점과 대응

단점BlockStep에서의 영향대응
네이티브 엔진보다 약간의 성능 손실작음. 이 게임은 2D 수준이고, WebGL은 크롬·사파리와 같은 엔진입니다성능 최적화 후 저가형 안드로이드에서 실측
안드로이드 기기마다 WebView 버전이 다름아주 오래된 기기에서 3D 화면이 안 열릴 수 있음최소 지원 버전 지정 (Android 7 이상), 이미 있는 "3D 화면을 열 수 없어요" 안내 유지
iOS 웹뷰 메모리 제한이 엄격함17만 블록 내보내기 때 위험지금도 256행씩 나눠 만드는 방식이라 대응돼 있음. 네이티브 파일 쓰기로 메모리를 더 줄임
소리 세션, 사진 저장은 웹 기능만으로 부족사진 앱 저장, 다른 앱 음악과의 관계공식·소형 플러그인으로 해결 (아래 4장)
앱 시작 시 웹뷰 로딩 0.3~1초첫 화면이 잠깐 늦을 수 있음스플래시 화면으로 가림
애플 4.2 심사 위험낮음. 오프라인 게임이기 때문모든 자산을 앱에 내장, 외부 웹 로딩 없음
Mac 없이는 iOS 디버깅이 어려움iOS 전용 문제를 바로 보기 어려움TestFlight 실기기 테스트, 관리자 패널의 기기 상태 표시 활용
수정 사항 반영에 스토어 심사 필요웹처럼 즉시 반영되지 않음내부 테스트 트랙과 TestFlight로 빠르게 확인

결론: 지금 수준의 게임에는 Capacitor가 가장 적합합니다. 다시 개발하는 방식(Unity, Flutter 등)보다 퀄리티 유지와 일정 면에서 확실히 유리합니다.

4. 다른 앱 음악과의 관계 (질문 7)

가능합니다. 환경음 선택에 따라 휴대폰의 "소리 모드"를 바꿉니다.

환경음 선택다른 앱 음악 (멜론, 스포티파이 등)블록 효과음
끄기 (X)계속 재생음악 위에 섞여서 남
거리, 비멈춤 (BlockStep 환경음 우선)그대로 남
  • iOS: 끄기일 때는 "Ambient" 모드(다른 음악과 섞임), 환경음이 켜지면 "Solo Ambient" 모드(다른 음악을 멈춤)로 바꿉니다. 두 모드 모두 무음 스위치를 켜면 소리가 꺼집니다. 지금 웹 버전과 같은 동작이고, 대부분의 캐주얼 게임이 이렇게 합니다.
  • Android: 환경음이 켜지면 "오디오 포커스"를 요청해 다른 앱 음악을 멈추고, 끄면 포커스를 돌려줍니다. 다만 다른 앱이 자동으로 다시 재생되는지는 그 앱의 정책에 따릅니다(스포티파이는 보통 사용자가 직접 다시 재생).
  • 둘 다 작은 네이티브 플러그인으로 구현하며, 실기기에서 확인합니다.

확인 부탁: 환경음이 켜져 있을 때 무음 스위치를 켜면 환경음도 꺼지는 위 동작으로 진행해도 될까요? 무음이어도 환경음이 나오게 할 수도 있지만, 공공장소에서 갑자기 소리가 날 위험이 있어 권하지 않습니다.

5. 용량 최적화

작업효과퀄리티 보장 방법
아침·밤 소리 제외 (원본 보존)−29MB현재 선택할 수 없는 소리라 영향 없음
거리·비 환경음을 AAC 128kbps 모노로 재인코딩약 24MB → 약 9MBA/B 비교 페이지를 드리고, 귀로 차이를 못 느끼는 것을 확인받은 뒤 적용
Lottie 재생기를 가벼운 공식 재생기(lottie-web)로 교체약 −1MB두 재생기의 모든 프레임을 픽셀 단위로 비교하고, 차이가 있으면 교체하지 않음
효과음 WAV, 손글씨 폰트, 블록 이미지유지이득이 작고 품질과 직결되어 그대로 둠

예상 설치 크기: 55MB → 약 15MB 안팎

6. 발열·렉 최적화

  1. 필요할 때만 그리기: 일시정지나 대기 중이면서 비가 없을 때는 그리기를 쉽니다. 조작 중에는 기기 최고 주사율(120Hz)을 그대로 씁니다.
  2. 보드 저장 구조 압축: 문자열 Map을 숫자 배열로 바꿔 17만 블록에서도 메모리를 수 MB로 유지합니다. 게임 규칙은 동일하며 단위 테스트로 검증합니다.
  3. 비 객체 재사용: 빗방울, 동심원, 젖은 자국을 미리 만들어 돌려 써서 끊김을 없앱니다.
  4. 앱이 백그라운드로 가면 그리기, 효과음, 환경음을 완전히 멈춥니다.
  5. 묶음 그리기(인스턴싱): 화면 안 블록은 최대 약 150개라 이미 부담이 작습니다. 게다가 블록이 겹치는 순서가 미세하게 달라질 위험이 있습니다. 그래서 측정해 보고 효과가 있을 때만 적용합니다.
  6. 검증: ?stress=로 17만 블록 상황을 만들어 프레임, 메모리, 그리는 횟수를 전후로 비교합니다.

7. 기기별 확인 환경

① 기기 미리보기 페이지 (새로 구현, 개발 전용)

한 화면에 아래 기기들의 크기로 게임을 동시에 띄웁니다. 각각 세로·가로 전환과 노치·홈 바 같은 안전 영역 흉내를 지원합니다. 출시 빌드에는 들어가지 않습니다.

  • 갤럭시 S 시리즈, Z 플립, Z 폴드(접힘·펼침)
  • 아이폰 SE, 일반, Pro Max
  • 아이패드, 갤럭시 탭

앱은 세로 고정이지만, 가로 미리보기에서는 태블릿을 가로로 들었을 때 회전하지 않는 화면을 확인할 수 있습니다. 화면 비율과 배치만 흉내 내므로 성능과 소리는 실기기에서 확인해야 합니다.

② 실제 에뮬레이터

  • Android Studio(무료, Windows): 픽셀 폰, 폴더블, 태블릿 에뮬레이터를 쓸 수 있습니다. 앱 빌드에도 필요하므로 설치가 필요합니다(10장).
  • iOS 시뮬레이터: Mac 전용이라 대신 TestFlight로 실제 아이폰에서 확인합니다.

8. 관리자 조절 패널

  • 항목마다 게이지바와 숫자 입력칸을 둡니다. 바꾸면 게임에 바로 반영됩니다.
  • '기본값으로' 버튼과 '설정값 복사' 버튼을 둡니다. 기획자가 확정한 값을 복사해 전달하면, 개발에서 정식 기본값으로 반영합니다.
  • 웹에서는 주소 뒤에 ?admin을 붙여 엽니다. 앱에서는 테스트 빌드에서만 열 수 있고, 출시 빌드에는 들어가지 않습니다.

9. 유저 데이터 분석 (Firebase Analytics)

별도 관리자 페이지는 만들지 않아도 됩니다. Firebase 콘솔이 리텐션(D1, D7, D30), 활성 사용자, 세션 길이, 퍼널(이탈 지점)을 기본 대시보드로 보여줍니다. 더 깊은 분석이 필요해지면 BigQuery로 원본 데이터를 내보내 직접 쿼리할 수 있습니다.

수집할 이벤트 (초안)

이벤트알 수 있는 것
앱 실행 → 첫 터치 → 첫 블록 → 블록 10·100·1,000개어디서 이탈하는지 (퍼널)
환경음 선택, 환경별 재생 시간어떤 환경음을 많이 쓰는지
세션 시작·종료, 플레이 시간 (Firebase 자동 수집)얼마나 자주, 오래 즐기는지
일시정지, 내보내기 시도·완료·취소, 새로 쌓기핵심 기능 사용률
  • 걸음 수와 건강 데이터는 보내지 않습니다.
  • 광고 ID를 쓰지 않으므로 iOS 추적 동의 팝업은 필요 없습니다.
  • 필요한 것: 개인정보처리방침 웹페이지(노션 공개 페이지도 가능), 스토어별 데이터 수집 신고(애플 '앱 개인정보', 구글 '데이터 보안').
  • 개발 빌드와 웹 테스트 데이터는 분석에 섞이지 않게 구분합니다.

직접 하실 일: Firebase 프로젝트 만들기

  1. console.firebase.google.com에 Play Console과 같은 구글 계정으로 로그인 → '프로젝트 추가' → 이름 BlockStep → Google 애널리틱스 '사용' 선택
  2. 프로젝트 화면에서 Android 아이콘 → 패키지 이름(앱 ID) 입력 → google-services.json 다운로드 → 저에게 경로를 알려주시면 연결합니다
  3. iOS는 Apple 개발자 등록 후 같은 방식으로 GoogleService-Info.plist를 받습니다

10. Google Play 테스트 빌드 올리기 (태블릿에서 바로 테스트)

A. 가장 빠른 방법: USB로 직접 설치 (심사 없음, 당일 가능)

  1. Android Studio 설치: developer.android.com/studio에서 내려받아 기본 옵션으로 설치하고, 첫 실행 마법사를 끝까지 진행합니다. 빌드 도구(SDK, Java)가 함께 깔리며 약 10GB가 필요합니다.
  2. 태블릿 개발자 모드 켜기: 설정 → 태블릿 정보 → 소프트웨어 정보 → '빌드 번호'를 7번 탭 → 설정 → 개발자 옵션 → 'USB 디버깅' 켜기
  3. USB로 PC에 연결하고 태블릿에 뜨는 '이 컴퓨터 허용'을 누릅니다
  4. 제가 명령 한 줄로 빌드하고 설치합니다

B. 정식 경로: Play Console 내부 테스트

  1. 앱 만들기: Play Console → '앱 만들기' → 앱 이름 / 기본 언어 한국어 / '게임' / '무료' → 선언 체크 → 만들기
  2. 업로드 키 만들기: 제가 Android Studio의 서명 키 파일(.jks)을 만드는 과정을 안내합니다.

    키 파일과 비밀번호는 반드시 두 곳 이상에 백업해야 합니다(USB, 클라우드 등). 잃어버리면 업데이트를 올리기가 매우 번거로워집니다. Git에는 올리지 않습니다.

  3. 앱 번들 만들기: 제가 서명된 .aab 파일을 만듭니다. 이 파일이 스토어에 올리는 앱 파일입니다.
  4. 업로드: Play Console → 테스트 및 출시 → 테스트 → 내부 테스트 → '새 버전 만들기' → Play 앱 서명 '계속'(구글이 최종 서명 키를 안전하게 보관) → .aab 끌어다 놓기 → 버전 이름·출시 노트 입력 → 저장 → 검토 → 출시
  5. 테스터 등록: 내부 테스트 → '테스터' 탭 → 이메일 목록 만들기 → 태블릿의 구글 계정 추가 → 저장
  6. 설치: 같은 화면의 '참여 링크'를 태블릿에서 열기 → '테스터 되기' → Play 스토어에서 설치. 내부 테스트는 심사 없이 보통 몇 분 안에 열립니다.

C. 정식 출시까지 (나중 단계)

  • 앱 콘텐츠 작성: 개인정보처리방침 URL, 광고 없음, 콘텐츠 등급 설문, 타깃 연령, 데이터 보안(Firebase 수집 항목 신고)
  • 스토어 등록정보 작성: 아이콘 512×512, 그래픽 이미지 1024×500, 휴대폰 스크린샷 2장 이상, 태블릿 스크린샷(태블릿 노출에 유리), 짧은 설명(80자), 자세한 설명
  • 중요2023년 11월 이후 만든 개인 계정은 정식 출시 전에 테스터 12명 이상이 14일 연속 참여하는 비공개 테스트를 통과해야 합니다. 사업자(조직) 계정은 해당되지 않습니다. 계정 유형을 알려주세요.
  • Play가 요구하는 최신 targetSdk(매년 상향)를 맞춰 빌드합니다.

11. iOS 처음부터 출시하기 (Mac 없이)

  1. Apple ID 2단계 인증 켜기: 아이폰 설정 → 이름 → 로그인 및 보안 → 이중 인증
  2. Apple Developer Program 가입: developer.apple.com/programs/enroll → 아이폰의 'Apple Developer' 앱으로 가입하면 신분 확인이 빠릅니다. 연 99달러(약 13만 원)이며, 개인 또는 조직(D-U-N-S 번호 필요)을 선택합니다. 승인까지 보통 1~2일, 길면 1주일이 걸리니 지금 바로 시작하는 것을 권합니다.
  3. 앱 등록: appstoreconnect.apple.com → 나의 앱 → '+' → 신규 앱 → 플랫폼 iOS / 이름 / 기본 언어 한국어 / 번들 ID / SKU(아무 고유 문자열, 예: blockstep-001)
  4. API 키 만들기: App Store Connect → 사용자 및 액세스 → 통합 → App Store Connect API → 키 생성(권한: App Manager) → .p8 파일 다운로드. 이 키로 클라우드 Mac이 인증서 발급과 업로드를 자동으로 처리합니다.
  5. Codemagic 연결: codemagic.io에 GitHub 계정으로 가입 → 저장소 연결 → API 키 등록. 빌드 설정 파일(codemagic.yaml)은 제가 만듭니다. 개인 사용은 매달 무료 빌드 시간이 있어 테스트 단계에서는 보통 무료로 충분합니다.
  6. 빌드 시작: Codemagic에서 'Start build'를 누르면 클라우드 Mac이 빌드해 TestFlight에 자동 업로드합니다(20~40분).
  7. TestFlight 설치: 아이폰에 TestFlight 앱 설치 → App Store Connect의 TestFlight 탭에서 내부 테스터로 본인 추가 → 초대 메일로 설치. 내부 테스터(최대 100명)는 심사 없이 바로 설치할 수 있습니다.
  8. 심사 제출(정식 출시 때): 스크린샷(6.9인치 아이폰 필수, 아이패드 지원 시 13인치 아이패드), 설명, 개인정보처리방침 URL, 앱 개인정보 설문, 연령 등급, 카테고리(게임 › 캐주얼)를 작성하고, 수출 규정 질문(암호화 사용)에는 '아니요'로 답한 뒤 제출합니다. 심사는 보통 1~2일 걸립니다.
